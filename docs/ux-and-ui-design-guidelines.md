# Germany Move Quest – UX & UI Design Guidelines

## Purpose

This document captures the user experience and interface design guidelines for Germany Move Quest.

It describes how the application's design principles are expressed through its user interface, interactions, language, and visual presentation.

The goal is to provide users with a calm, supportive, and consistent experience throughout their transition to life in Germany and beyond.

---

# User Experience

## A Companion, Not a Task Manager

The application should feel like a trusted companion throughout the user's journey rather than a traditional task manager.

The focus is on providing guidance, reducing uncertainty, and building confidence rather than simply completing checklists.

---

## Context Before Action

Users should understand why something matters before being asked to act.

Recommendations should include enough context for users to make informed decisions without overwhelming them with unnecessary detail.

---

## One Primary Purpose Per Page

Each page should have a clearly defined purpose.

Pages should avoid competing priorities and multiple primary calls to action.

Users should always understand what the page is intended to help them accomplish.

---

## Progress, Not Tasks

The application emphasizes meaningful progress rather than task completion.

Recommendations, milestones, and achievements should help users understand how they are progressing through their journey.

---

## Helpful Guidance

The application should explain:

* why something matters
* when it becomes relevant
* what happens next

Guidance should reduce uncertainty rather than simply present information.

---

# Language

## German Teaches. English Reassures.

German terminology should appear wherever users will encounter it in everyday life, for example terms like "Anmeldung" when registering your address.

English should provide explanation, reassurance, and confidence.

The objective is practical familiarity rather than formal language instruction.

---

## Use Real-World Terminology

Whenever practical, terminology should match what users will encounter in Germany.

Examples include government processes, public transport, shopping, and everyday life.

Page titles should match the navigation labels.

---

# Visual Design

## Calm, Not Corporate — and a Little Fun

The interface should reduce stress through thoughtful visual design.

Favour:

* generous whitespace
* restrained colour usage
* subtle shadows
* rounded corners
* minimal visual clutter

The interface should feel welcoming rather than institutional.

---

## Visual Hierarchy

Important information should naturally attract attention.

Use spacing, typography, grouping, and contrast to establish clear visual hierarchy before relying on colour or decoration.

Primary actions should be obvious without dominating the page.

---

## Consistency Over Novelty

Reusable design patterns should always be preferred over unique one-off solutions.

Consistency reduces cognitive effort and makes the application easier to learn.

---

# Interaction Design

## Interactive Things Should Look Interactive

Buttons, links, cards, selectors, and editable controls should clearly communicate that they can be interacted with.

Visual affordances should be consistent throughout the application.

---

## Progressive Disclosure

Present information in manageable amounts.

Show what is relevant now while allowing additional detail to be revealed when needed.

---

## Empty States Should Still Be Useful

When no content is available, the interface should continue providing value.

Empty states should explain the situation, reinforce the page's purpose, or help users understand what comes next.

---

# Responsive Design

## Mobile First

Germany Move Quest is designed primarily for mobile devices because many relocation activities happen in the real world.

Desktop layouts should take advantage of additional space without simply stretching the mobile interface.

---

## Responsive, Not Resized

Layouts should adapt thoughtfully to different screen sizes.

Responsive design should improve readability, hierarchy, and usability rather than simply rearranging content.

---

# Components

## Reusable Components

Shared components should provide a consistent experience throughout the application.

Whenever practical, new features should build upon existing components rather than introducing new interaction patterns.

---

## Cards

Cards are the primary organizational element within the application.

They should present related information clearly, maintain consistent spacing, and avoid unnecessary visual complexity.

---

## Icons

Use Lucide icons consistently throughout the application.

Icon selection should be centralized through the Icon Catalog whenever practical.

Icons should communicate meaning rather than provide decoration.

---

# Journey Presentation

The interface should reinforce that relocating to Germany is an ongoing journey rather than a finite checklist.

For example, the Journey timeline intentionally extends beyond the final stage to visually communicate that Germany Move Quest continues supporting users as they settle into everyday life and build a home in Germany.
